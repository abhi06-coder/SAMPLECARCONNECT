Chapter 4: Methodology

4.1 Software Engineering Process

The Software Engineering Process for the CarConnect platform follows a structured, systematic approach to ensure the development of a robust, reliable, and user-centric solution. The process involves several phases, each focusing on delivering high-quality software while adhering to best practices and meeting the project requirements. Below are the key phases of the software engineering process:

1. Requirement Gathering and Analysis
• Objective: Understand and gather all functional and non-functional requirements of the system from stakeholders (commuters, car owners, college students).
• Activities:
• User Interviews: Conducted interactions with daily commuters and students to gather insights on their travel patterns, route difficulties, and safety concerns.
• Stakeholder Meetings: Engaged with potential users to understand the requirements for payment security, profile verification, and ride scheduling.
• Documentation: Created detailed documentation of the gathered requirements and prepared use cases such as "Offering a Ride", "Booking a Seat", and "Wallet Recharge".
• Outcome: A clear understanding of what the platform must achieve, formatted as a detailed Software Requirements Specification (SRS) document.

2. System Design
• Objective: Design the architecture of the system, ensuring it meets the functional requirements and is scalable, secure, and user-friendly.
• Activities:
• High-Level Design (HLD): Defined the overall MERN architecture, including the MongoDB schema, React component hierarchy, and integration points with Razorpay and Firebase.
• Low-Level Design (LLD): Designed specific modules such as the "Virtual Grid" algorithm for seat management, the search query logic, and the JWT authentication flow.
• UI/UX Design: Developed wireframes and responsive layouts to ensure an intuitive interface, focusing on ease of access for mobile users on the go.
• Outcome: A well-defined system architecture (Client-Server model) and database schema design.

3. Implementation (Coding)
• Objective: Develop the system by translating the design into actual code, following modern web standards.
• Activities:
• Frontend Development: Implemented the user interface using React.js, Context API for state management, and CSS for styling. Ensured responsiveness for mobile devices.
• Backend Development: Built a robust REST API using Node.js and Express. Implemented the ride matching logic, geospatial queries, and wallet transaction controllers on the server side.
• Integration: Integrated external services:
    - Firebase for OTP Authentication.
    - Razorpay for Payment Gateway.
    - MongoDB Atlas for Cloud Database.
• Version Control: Used Git and GitHub for version control, branching, and collaboration.
• Outcome: A fully functional web application capable of handling real-world carpooling scenarios.

4. Testing
• Objective: Ensure the system functions as expected, is free of defects, and meets all requirements.
• Activities:
• Unit Testing: Tested individual API endpoints (e.g., /api/make-payment, /api/search-rides) using Postman to ensure logic correctness.
• Integration Testing: Verified that the Frontend correctly communicates with the Backend and that database updates trigger the correct UI changes.
• System Testing: Tested the entire user flow: Sign up -> Search Ride -> Book Seat -> Payment -> Completion.
• User Acceptance Testing (UAT): Conducted testing with peer groups to validate the usability of the wallet system and search filters.
• Outcome: A stable, bug-free platform ready for deployment.

5. Deployment
• Objective: Launch the system in a live environment for public use.
• Activities:
• Environment Setup: Configured environmental variables (.env) for production, including API keys and database strings.
• Deployment Process: Deployed the Client and Server artifacts to hosting platforms (e.g., Vercel/Render), ensuring continuous integration.
• Monitoring: Monitored the application for runtime errors and database connection stability.
• Outcome: The CarConnect platform is live and accessible via a public URL.

6. Maintenance and Updates
• Objective: Provide ongoing support and enhancements for the platform after deployment.
• Activities:
• Bug Fixes: Addressing issues reported by users, such as payment timeouts or search glitches.
• Feature Enhancements: Adding new capabilities like "Recurring Rides" or "Chat Integration" based on user feedback.
• Security Updates: ensuring dependencies are up to date to prevent vulnerabilities.
• Outcome: A continually improving platform that adapts to user needs and remains reliable.

7. Documentation and Training
• Objective: Provide complete documentation for maintaining the system.
• Activities:
• User Guides: Instructions on how to verify profiles, add money to wallets, and manage bookings.
• Developer Documentation: Inline code comments, API documentation, and setup guides for future developers.
• Outcome: Comprehensive knowledge base ensuring the project's longevity.

The Software Engineering Process for CarConnect is a structured approach that leverages the MERN stack's flexibility. By following these steps—from requirement gathering to deployment—we ensured that CarConnect effectively solves the real-world problem of urban congestion while providing a seamless user experience.

4.2 Work Tasks Identified

The development of CarConnect involves multiple tasks spread across different phases of the project lifecycle. Each task contributes to the successful implementation of the platform and ensures that the system meets its functional and non-functional requirements. Below is a breakdown of the key tasks:

1. Requirement Analysis & Planning
• Understand Problem Scope: Analyze the problem statement related to urban mobility and research existing challenges in carpooling adoption (trust, coordination).
• Identify Key Features: Define essential functionalities such as Virtual Grid routing, Wallet integration, and Verified Profiles.
• Stakeholder Discussion: Collaborate with daily commuters, students, and vehicle owners to understand pain points.
• Prepare Software Requirement Specification (SRS): Document all technical and functional requirements including API endpoints and database constraints.

2. System Design
• Design System Architecture: Define high-level MERN architecture, including the React frontend, Node.js backend, and Cloud Database integration.
• Database Schema Development: Plan and design MongoDB collections for storing user data, rides, bookings, transactions, and reviews.
• UI/UX Design: Create wireframes and user interface designs for the mobile-responsive platform.
• Define APIs & Integrations: Plan API structures for ride matching, payment gateway (Razorpay), and map services.

3. Development (Implementation)

Frontend Development
• Develop User Interface: Implement the UI using React.js, Tailwind CSS/Bootstrap, and Context API.
• Ensure Responsiveness: Make the platform mobile-friendly for users on the go.
• Integrate User Forms: Develop forms for Ride Creation, Profile Verification, and Feedback.
• Design Interactive Tools: Implement fare estimation and carbon saving calculators.

Backend Development
• Set Up Database: Use MongoDB Atlas to manage user profiles, ride listings, and wallet balances.
• Develop Ride Matching System: Implement the "Virtual Grid" algorithm to analyze route coordinates and suggest seat availability.
• Implement Business Logic: Code functionalities for booking management, cancellation penalties, and refund processing.
• Integrate APIs: Connect with external services like Firebase (Auth) and Razorpay (Payments).

4. Testing & Quality Assurance
• Unit Testing: Test individual modules like fare calculators, auth middleware, and ride search logic.
• Integration Testing: Ensure that the React frontend, Node backend, and MongoDB database sync seamlessly.
• Performance Testing: Optimize API response times and database indexing for geospatial queries.
• User Acceptance Testing (UAT): Conduct trials with a closed group of users to gather feedback on the flow and ease of booking.

5. Deployment & Maintenance
• Server Setup: Deploy the application to a live hosting environment (e.g., Vercel for client, Render for server).
• Data Migration: Ensure stable environment variables and load initial logic for admin accounts.
• Launch & Monitoring: Go live and continuously monitor system health via logs.
• Bug Fixes & Updates: Regularly patch reported bugs and enhance features based on user feedback.

6. Documentation & User Training
• Prepare User Guides: Create tutorials on how to verify profiles and add money to the wallet.
• Developer Documentation: Provide code structure, API references, and architecture diagrams.
• Onboarding Flow: Design in-app guidance for first-time drivers and passengers.

Effort Estimation (Using COCOMO Model - Basic Formula)

COCOMO Basic Effort Estimation Formula:
E = a * (KLOC) ^ b

Where:
• E = Effort in person-months
• a, b = Constants based on project type (for an organic project: a = 2.4, b = 1.05)
• KLOC = Total estimated LOC in thousands of lines of code

For the estimated size of 12.5 KLOC:
E = 2.4 * (12.5) ^ 1.05 = ~34 person-months

Project Team Size: 4 Developers

Duration Estimation:
Duration = Effort / Team Size
Duration = 34 / 4 = ~8.5 Months

Conclusion:
• The project is estimated to have approximately 12,500 Lines of Code.
• The total development effort is estimated at 34 person-months.
• With a team of 4 developers, the project can be completed in approximately 8.5 months.
• LOC-based estimation provides an approximate size and effort for project planning and resource allocation.
